## What happens step by step

### 1. Fixtures (`tests/conftest.py`)

```python
@pytest.fixture(scope="session")
def tiny_chunks(tiny_pdf: Path) -> list[Chunk]:
    return ingest_pdf(tiny_pdf, "tiny")


@pytest.fixture
def memory_store(tiny_chunks, embeddings) -> QdrantStore:
    store = QdrantStore(make_client(":memory:"), "test_chunks", embeddings.dim)
    store.ensure_collection()
    store.upsert(tiny_chunks, embeddings.embed([c.embed_text for c in tiny_chunks]))
    return store
```

A test gets a fixture just by naming it as a parameter. `scope="session"` = build once
(parsing the PDF), the default = fresh per test (the store, so tests can't affect each
other).

### 2. Fakes, not mocks

| Real | Fake in tests | Why it's a *fake* |
|---|---|---|
| ONNX embedder | `FakeEmbedder` (hashing-trick bag of words) | real behavior: shared words → similar vectors |
| cross-encoder | `FakeReranker` (word overlap) | real scores 0..1, threshold works |
| LLM | `FakeProvider` (cites the first context chunk with a real quote) | Verify really passes |
| Qdrant server | `QdrantClient(":memory:")` | the same client API, the real query semantics incl. RRF |
| HTTP | `httpx.MockTransport` | a fake server function, no sockets |

A **mock** records calls and returns canned values ("was `embed` called with X?"). A
**fake** is a small working implementation. Fakes test *behavior* ("the table question
retrieves the table chunk") and survive refactors; mocks tend to test implementation details.
The fakes live in `src/` (not `tests/`) because the E2E test and `configs/e2e_fake.yaml` use
them too.

### 3. Mocking HTTP (`tests/unit/test_openai_compat.py`)

```python
def handler(request: httpx.Request) -> httpx.Response:
    seen.append(request)
    return _ok('{"answer": "x", "evidence": []}')


provider = OpenAICompatProvider(
    "t", "http://x/v1", "key", transport=httpx.MockTransport(handler)
)
```

The test asserts the request body (`response_format.json_schema.strict == True`, auth
header) and the mapping back (usage, think-tag stripping, 429 retry, 400 no retry).
It's the same idea as MockWebServer in Java or msw/nock in JS.

### 4. API tests (`tests/unit/test_api.py`)

```python
app = create_app(service, pdf_dir=tiny_pdf.parent)
with TestClient(app) as c:
    yield c
```

`TestClient` calls the ASGI app in-process, with no port and no server (Spring MockMvc,
supertest). The `with` block runs the lifespan. The fixture `yield`s; code after
the yield is teardown.

### 5. The E2E test (`tests/e2e/`)

Marked `@pytest.mark.e2e` and skipped unless `DOCRAG_E2E_QDRANT_URL` is set. It runs the
real parser on `fixtures/tiny.pdf`, writes into a **real Qdrant server**, and queries through
the real FastAPI app with fake embedder/LLM. That proves wiring + server
behavior (payload index, sparse IDF, RRF on the server) without model downloads in CI.

Locally:

```powershell
docker compose up -d qdrant
$env:DOCRAG_E2E_QDRANT_URL = "http://localhost:6333"; uv run pytest -m e2e
```

### 6. CI (`.github/workflows/ci.yml`)

Three parallel jobs on every push/PR:

1. **lint-test:** `uv sync --locked` → `ruff check` → `ruff format --check` → `mypy src`
   → `pytest -m "not e2e"`.
2. **e2e:** a Qdrant **service container** (`qdrant/qdrant:v1.20.0`, same tag as
   compose), poll `/readyz` until ready (not a fixed sleep), then `pytest -m e2e`.
3. **docker:** `docker build`, so a broken Dockerfile fails the PR, not the deploy.

`--locked` fails if `uv.lock` and `pyproject.toml` disagree. `concurrency:
cancel-in-progress` cancels outdated runs of the same branch.

### 7. Docker (`Dockerfile`, `compose.yaml`)

Multi-stage build:

- **builder:** `python:3.12-slim` + the uv binary copied from its official image;
  `uv sync --locked --no-dev --no-install-project` first (dependency layer, cached
  as long as `pyproject.toml`/`uv.lock` don't change), then copy `src/` and install the project.
- **runtime:** a fresh slim image, copy only `.venv`, configs, fixtures; run as a
  non-root user (`uid 10001`); `PYTHONUNBUFFERED=1` so logs appear immediately.

`compose.yaml`: `qdrant` with a named volume (the index survives `down`), and `api` built
from the Dockerfile, reaching Qdrant by service name `http://qdrant:6333`, Ollama on the
host via `host.docker.internal`, and API keys from an optional `.env`. PDFs are mounted
read-only, while models and the cache are mounted so they're downloaded and computed only once.

## Why this design

> - **Fast, deterministic unit tests:** no network, no model downloads; the whole suite
>   runs in seconds on Windows and Linux.
> - **One real E2E:** catches what fakes can't (server-side Qdrant behavior, the
>   serialization of payloads), with minimal flakiness.
> - **Lock-file-based CI and Docker:** the same dependency versions everywhere.
> - **Multi-stage + non-root:** smaller image, smaller attack surface.

## Python concepts

### pytest basics

```python
import pytest


@pytest.mark.parametrize(("a", "b", "expected"), [(1, 2, 3), (0, 0, 0)])
def test_add(a: int, b: int, expected: int) -> None:
    assert a + b == expected


def test_raises() -> None:
    with pytest.raises(ValueError):
        int("x")


async def test_async() -> None:  # works thanks to asyncio_mode = "auto"
    assert await some_coroutine() == 1
```

Plain `assert`: pytest rewrites it to show both sides on failure. `parametrize` ≈ JUnit
`@ParameterizedTest`. Your own `tests/unit/test_ids.py` already uses it.

### Markers

`@pytest.mark.e2e` + `markers = [...]` in pyproject + `pytest -m "not e2e"` → select or
deselect groups of tests.

### Generator fixtures

```python
@pytest.fixture
def resource():
    r = open_it()
    yield r  # the test runs here
    r.close()  # teardown, even if the test failed
```

## Interview questions

**Q: How do you test an LLM application without paying for API calls?**
A: The LLM sits behind a Provider interface; tests use a FakeProvider that produces
realistic structured answers from the prompt, and the HTTP adapters are tested against
`httpx.MockTransport`. The embedder, reranker and vector store have fakes or an in-process mode too.
Paid models only run in the benchmark, behind the cache.

**Q: Fakes or mocks?**
A: Mostly fakes: small working implementations. They test behavior and survive
refactors. Mocks only at the HTTP boundary, where the point is to assert the exact
request format.

**Q: What does your E2E test prove that unit tests don't?**
A: That the real parser, a real Qdrant server (payload index, sparse IDF, server-side
RRF), and the FastAPI app work together over the network. It runs in CI against a
Qdrant service container.

**Q: What's in your CI pipeline?**
A: Lint, format check, mypy strict and unit tests; a separate E2E job with a Qdrant
service container; and a Docker build check. All of them run from the lockfile.

**Q: Explain your Dockerfile.**
A: It's a multi-stage build. A builder stage uses uv to create the venv from the lockfile,
installing dependencies before copying the source for layer caching. The runtime stage copies only the venv and runs as
a non-root user. Models, data and cache are mounted volumes, not baked into the image.

**Q: What isn't tested?**
A: The real ONNX models and real LLM providers in CI (too slow and costly); they're
exercised by the benchmark runs. The Windows CI matrix is future work; development
happens on Windows, CI runs on Linux.
